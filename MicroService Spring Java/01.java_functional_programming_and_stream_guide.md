# Java 함수형 프로그래밍, 람다 표현식, Stream API 및 Project Reactor 완벽 가이드

이 문서는 **Project Reactor(`Flux`)** 코드에서 출발하여, **일반적인 명령형 코딩(`for` 문)**과 **표준 Java Stream API**, **함수형 프로그래밍 패러다임**, **람다 표현식**, **메서드 참조**, 그리고 **실무 DB-to-UI 데이터 처리 패턴(`flatMap`, `Optional`, `groupingBy`)**까지 전체 개념을 체계적으로 정리하고 보완한 학습 가이드입니다.

---

## 1. Project Reactor vs. 일반 코딩 비교

Project Reactor의 `Flux`를 사용한 비동기·논블로킹 리액티브 코드는 일반적인 Java 환경에서 **전통적인 반복문(`for` 문)**이나 **표준 Java Stream API**로 대체하여 직관적인 동기식(Synchronous) 코드로 작성할 수 있습니다.

### 1.1 원본 코드: Project Reactor (`Flux`) 방식
```java
@Test
void testFlux() {
    List<Integer> list = Flux.just(1, 2, 3, 4)
        .filter(n -> n % 2 == 0)
        .map(n -> n * 2)
        .log()
        .collectList()
        .block();

    assertThat(list).containsExactly(4, 8);
}
```
* **특징**: 데이터가 비동기적으로 흘러오는 파이프라인을 설계한 뒤, 마지막에 `.block()`을 호출해 구독자를 등록하고 처리가 완료될 때까지 기다려 결과를 수집합니다.

### 1.2 대안 ①: 가장 기본적인 반복문(`for` 문) 방식 (명령형 프로그래밍)
데이터를 하나씩 꺼내어 조건을 확인하고 새로운 리스트에 직접 담는 전통적인 방식입니다.
```java
@Test
void testImperative() {
    List<Integer> numbers = Arrays.asList(1, 2, 3, 4);
    List<Integer> list = new ArrayList<>();

    for (Integer n : numbers) {
        if (n % 2 == 0) {                // 1. 짝수 필터링
            int doubled = n * 2;         // 2. 값을 2배로 변환
            System.out.println(doubled); // 3. 로그 출력
            list.add(doubled);           // 4. 결과 리스트에 추가
        }
    }

    assertThat(list).containsExactly(4, 8);
}
```

### 1.3 대안 ②: 표준 Java Stream API 방식 (Java 8 이상)
Project Reactor 코드와 문법 구조가 가장 비슷하지만, 비동기 스트림(`Flux`)이 아닌 **메모리 내 컬렉션 기반의 동기식 스트림(`Stream`)**을 사용합니다.
```java
@Test
void testJavaStream() {
    List<Integer> list = List.of(1, 2, 3, 4).stream()
        .filter(n -> n % 2 == 0)
        .map(n -> n * 2)
        .peek(System.out::println) // 로그 출력용
        .toList();                 // Java 16 이상 (이전 버전은 .collect(Collectors.toList()))

    assertThat(list).containsExactly(4, 8);
}
```

### 1.4 Project Reactor vs. 표준 Java Stream 핵심 비교

| 비교 항목 | Project Reactor (`Flux`) | 표준 Java Stream | 일반 `for` 반복문 |
| :--- | :--- | :--- | :--- |
| **패러다임** | 리액티브 / 함수형 / 선언형 | 함수형 / 선언형 | 명령형 (Imperative) |
| **데이터 위치** | 네트워크나 DB에서 **언제 도착할지 모르는** 미래의 데이터 | 이미 **메모리에 모두 올라와 있는** 컬렉션 | 메모리에 있는 컬렉션/배열 |
| **실행 방식** | **비동기 / 논블로킹** (이벤트 기반 예약 실행) | **동기 / 블로킹** (위에서 아래로 순차 실행) | **동기 / 블로킹** (즉시 실행) |
| **실행 트리거** | `.block()`이나 `.subscribe()` 호출 시 동작 | **최종 연산**(`.toList()`, `.count()`) 호출 시 동작 | 코드 라인에 도달하면 즉시 동작 |
| **데이터 흐름** | 데이터가 준비되면 밀어 넣어주는 방식 (**Push**) | 데이터를 당겨오는 방식 (**Pull**) | 인덱스로 직접 접근하여 꺼냄 |
| **재사용 여부** | 파이프라인(설계도)을 여러 번 구독하여 재사용 가능 | **일회용** (최종 연산 후 닫히므로 재사용 불가) | 언제든 다시 반복문 실행 가능 |

## 2. 핵심 프로그래밍 용어 및 패러다임 정리

함수형 스타일로 간결하게 코드를 작성할 때 자주 사용되는 핵심 용어들의 정확한 의미와 관계입니다.

* **명령형 프로그래밍 (Imperative Programming)**: `for`, `while`, `if` 등을 사용하여 컴퓨터가 수행할 절차와 상태 변경을 **"어떻게(How)"** 할지 일일이 지시하는 방식입니다.
* **선언형 프로그래밍 (Declarative Programming)**: 세부적인 반복 제어 과정은 감추고, **"무엇을(What)"** 원하는지 조건과 변환 규칙만 나열하여 가독성을 높이는 방식입니다.
* **함수형 프로그래밍 (Functional Programming)**: 데이터 원본을 직접 수정하지 않고(**불변성**), 외부 상태에 영향을 주지 않는 **순수 함수(Pure Function)**들을 조합해 데이터를 변환하는 프로그래밍 패러다임입니다. 부수 효과(Side Effect)를 최소화하여 코드의 예측 가능성과 테스트 용이성을 높입니다.
* **메서드 체이닝 (Method Chaining)**: `.filter().map().toList()`처럼 점(`.`)을 찍어 여러 메서드를 기차처럼 길게 연결해 작성하는 기법입니다. 데이터가 흘러가는 파이프라인 구조를 한눈에 보여줍니다.

## 3. 개념 계층 구조: 람다 vs. Stream vs. Project Reactor

세 개념은 서로 경쟁하거나 대체하는 관계가 아니라, **기초 문법에서 고급 확장 라이브러리로 이어지는 계층적 포함 관계**를 가집니다.

```text
[ Project Reactor ]  <-- 비동기/논블로킹 데이터 스트림 라이브러리 (외부 의존성 필요)
        ▲ (활용)
[ 표준 Java Stream ] <-- 메모리 컬렉션 동기식 파이프라인 API (Java 8 기본 내장)
        ▲ (활용)
[   람다 표현식   ]  <-- 이름 없는 함수를 간결하게 전달하는 언어 문법 (Java 8 기본 문법)
```

### 3.1 함수형 프로그래밍 vs. 람다 표현식

| 비교 항목 | 함수형 프로그래밍 (Functional Programming) | 람다 표현식 (Lambda Expression) |
| :--- | :--- | :--- |
| **개념의 성격** | 프로그래밍 **패러다임** (설계 방식, 철학) | 프로그래밍 언어의 **문법** (기능, 도구) |
| **주요 목적** | 부수 효과를 줄이고 예측 가능한 코드 작성 | 이름 없는 함수를 짧고 간결하게 표현 |
| **독립성** | 람다식 없이도 익명 클래스 등으로 구현 가능 | 함수형 프로그래밍 외에도 이벤트 리스너, 스레드 등에 활용 |
| **핵심 키워드** | 불변성, 순수 함수, 선언형 코드 | 익명 함수, 화살표(`->`), 코드 축약 |

### 3.2 코드 내 역할 분담 예시
```java
Flux.just(1, 2, 3, 4)        // [Project Reactor] 비동기 데이터 파이프라인 생성 엔진
    .filter(n -> n % 2 == 0) // [Reactor 연산자] + [람다 표현식: 짝수 판별 알맹이 로직]
    .map(n -> n * 2)         // [Reactor 연산자] + [람다 표현식: 2배 변환 알맹이 로직]
    .log();                  // [Project Reactor] 스트림 신호 로깅
```
* **Project Reactor / Java Stream**: 데이터가 흘러가는 **파이프라인 뼈대와 실행 엔진**을 담당합니다.
* **람다 표현식**: 각 단계의 괄호 안에서 **"구체적으로 어떤 조건으로 거르고 어떻게 변환할지"**에 대한 **비즈니스 로직 알맹이**를 전달합니다.

## 4. 람다 표현식(Lambda Expression) 상세 분석

람다 표현식은 메서드를 하나의 간결한 식(Expression)으로 표현하여, **코드 조각(동작) 자체를 데이터처럼 메서드 매개변수로 전달**할 수 있게 해주는 문법입니다.

### 4.1 람다 표현식의 문법 축약 과정
기본 형태인 `(매개변수) -> { 실행문 }`에서 컴파일러가 추론할 수 있는 요소들을 단계적으로 생략할 수 있습니다.

1. **기본 정석 형태**: `(int a, int b) -> { return a + b; }`
2. **매개변수 타입 생략**: `(a, b) -> { return a + b; }` (문맥상 타입 추론 가능)
3. **매개변수 괄호 생략**: `n -> { return n * 2; }` (매개변수가 **딱 1개**일 때만 가능, 0개 `()`나 2개 이상 `(a, b)`은 필수)
4. **중괄호 및 `return` 생략**: `n -> n * 2` (실행문이 **단 한 줄**일 때만 가능)
5. **블록 람다식 (Block Lambda)**: 로직이 여러 줄로 복잡할 때는 중괄호 `{}`를 유지하고 명시적으로 `return`을 작성합니다.
   ```java
   order -> {
       int discounted = (int) (order.getPrice() * 0.9);
       return new OrderDto(order.getId(), discounted);
   }
   ```

### 4.2 람다의 작동 원리: 표준 함수형 인터페이스 (`java.util.function`)
Java는 객체지향 언어이므로 함수만 단독으로 존재할 수 없습니다. 람다식은 사실 **추상 메서드가 딱 하나만 있는 인터페이스(함수형 인터페이스, `@FunctionalInterface`)**를 즉석에서 구현한 익명 객체입니다.

| 인터페이스명 | 추상 메서드 시그니처 | 입출력 구조 | 주요 사용처 및 예시 |
| :--- | :--- | :--- | :--- |
| **`Predicate<T>`** | `boolean test(T t)` | `T` ➔ `boolean` | **조건 판별**: `.filter(n -> n > 10)` |
| **`Function<T, R>`** | `R apply(T t)` | `T` ➔ `R` | **데이터 변환**: `.map(user -> user.getName())` |
| **`Consumer<T>`** | `void accept(T t)` | `T` ➔ `void` | **데이터 소비(출력/저장)**: `.forEach(x -> System.out.println(x))` |
| **`Supplier<T>`** | `T get()` | `()` ➔ `T` | **데이터 공급(생성)**: `.orElseThrow(() -> new RuntimeException())` |
| **`UnaryOperator<T>`** | `T apply(T t)` | `T` ➔ `T` | **동일 타입 변환** (`Function`의 특수형): `n -> n * 2` |
| **`BinaryOperator<T>`** | `T apply(T t1, T t2)` | `(T, T)` ➔ `T` | **동일 타입 두 개 병합**: `.reduce(0, (a, b) -> a + b)` |

## 5. 메서드 참조 (Method Reference, `::`)

메서드 참조는 람다 표현식이 **단 하나의 기존 메서드만 호출**하는 경우, 불필요한 매개변수 선언과 화살표(`->`)를 생략하고 **`::` (더블 콜론)** 기호를 사용해 가독성을 극대화하는 문법입니다.

### 5.1 실무에서 자주 쓰는 4가지 패턴

| 유형 | 문법 형태 | 람다 표현식 예시 | 메서드 참조 예시 | 설명 |
| :--- | :--- | :--- | :--- | :--- |
| **정적(Static) 메서드 참조** | `클래스명::메서드명` | `s -> Integer.parseInt(s)` | `Integer::parseInt` | 클래스의 static 메서드 호출 |
| **특정 객체의 메서드 참조** | `참조변수::메서드명` | `x -> System.out.println(x)` | `System.out::println` | 이미 생성된 특정 인스턴스의 메서드 호출 |
| **임의 객체의 메서드 참조** | `클래스명::메서드명` | `s -> s.toUpperCase()` | `String::toUpperCase` | 스트림을 통해 넘어오는 객체 자신의 메서드 호출 |
| **생성자 참조** | `클래스명::new` | `name -> new User(name)` | `User::new` | 새로운 객체 인스턴스 생성 |

### 5.2 적용 예시 및 주의사항
```java
List<String> strNumbers = List.of("10", "20", "30");

// 메서드 참조 적용
List<Integer> list = strNumbers.stream()
    .map(Integer::parseInt)      // s -> Integer.parseInt(s)
    .peek(System.out::println)   // n -> System.out.println(n)
    .toList();
```
* **주의사항**: 매개변수를 연산하거나(`n -> n * 2`), 부정 연산자(`!`)를 붙이거나(`s -> !s.isBlank()`), 두 개 이상의 메서드를 연속 호출할 때는 메서드 참조를 쓸 수 없으므로 일반 람다 표현식을 사용해야 합니다.

## 6. 실전 연습 문제 및 모범 답안

### 📝 문제
사용자 이름 목록에서 **공백이 아니고 길이가 4글자 이상인 이름**만 골라, **모두 대문자로 바꾼 뒤 콘솔에 출력하고 새로운 리스트에 담는** 명령형 코드를 Stream API와 메서드 참조를 활용한 선언형 코드로 리팩토링하세요.

```java
// [기존 명령형 코드]
List<String> rawNames = List.of("alice", "", "bob", "charlie", "   ", "david");
List<String> result = new ArrayList<>();

for (String name : rawNames) {
    if (!name.isBlank() && name.length() >= 4) {
        String upper = name.toUpperCase();
        System.out.println(upper);
        result.add(upper);
    }
}
```

### ✅ 모범 답안
```java
List<String> rawNames = List.of("alice", "", "bob", "charlie", "   ", "david");

List<String> result = rawNames.stream()
    .filter(name -> !name.isBlank())    // 1. 공백 제외 (부정 연산자 때문에 람다식 유지)
    .filter(name -> name.length() >= 4) // 2. 길이 조건 필터링 (가독성을 위해 조건 분리)
    .map(String::toUpperCase)           // 3. 대문자 변환 (메서드 참조 적용)
    .peek(System.out::println)          // 4. 중간 로깅 (메서드 참조 적용)
    .toList();                          // 5. 불변 리스트로 최종 수집

// 출력 결과: ALICE, CHARLIE, DAVID
```

## 7. 실무 복합 패턴: DB 조회부터 UI 전달까지

백엔드 실무에서 데이터베이스 엔티티(Entity)를 조회한 뒤, 비즈니스 로직을 수행하고 프론트엔드(UI) 전용 응답 객체(DTO)로 안전하게 변환하는 대표적인 4가지 실무 패턴입니다.

### 7.1 기본 파이프라인: 필터링, 정렬 및 UI DTO 변환 (`filter` + `sorted` + 블록 `map`)
쇼핑몰에서 회원의 주문 내역을 조회하여 취소 건을 제외하고, VIP 할인을 적용한 뒤 UI 화면에 맞게 포맷팅하는 예제입니다.

```java
@Service
@RequiredArgsConstructor
public class OrderService {

    private final OrderRepository orderRepository;

    public List<OrderUiResponse> getUserOrderHistoryForUi(Long userId, boolean isVip) {
        // 1. [DB 계층] 회원의 모든 주문 엔티티 조회
        List<OrderEntity> dbOrders = orderRepository.findByUserId(userId);

        // 2. [비즈니스 로직 & UI 변환 계층]
        return dbOrders.stream()
            // [람다 1] 취소된 주문 제외
            .filter(order -> order.getStatus() != OrderStatus.CANCELED)
            // [람다 2] 유효 결제 금액(0원 초과)만 통과
            .filter(order -> order.getTotalPrice() > 0)
            // [메서드 참조] 최근 주문일 순 내림차순 정렬
            .sorted(Comparator.comparing(OrderEntity::getOrderedAt).reversed())
            // [블록 람다] 비즈니스 계산 및 UI 전용 DTO 변환 (DB 엔티티 노출 방지)
            .map(order -> {
                int finalPrice = isVip 
                    ? (int) (order.getTotalPrice() * 0.9) 
                    : order.getTotalPrice();

                String formattedDate = order.getOrderedAt()
                    .format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm"));

                String statusLabel = (order.getStatus() == OrderStatus.DELIVERED) 
                    ? "배송완료" : "배송준비중";

                return new OrderUiResponse(
                    order.getOrderNumber(),
                    order.getProductName(),
                    finalPrice,
                    formattedDate,
                    statusLabel
                );
            })
            .toList();
    }
}
```

### 7.2 1:N 중첩 데이터 평탄화 (`filter` + `flatMap` + `filter`)
주문 1건(`Order`) 안에 여러 개의 상품(`OrderItem`) 리스트가 들어있는 1:N 구조에서, 주문 단위가 아닌 **개별 상품 목록**만 쭉 펼쳐서 UI에 전달할 때 사용합니다.
* **`map` vs. `flatMap`**: `map`은 요소를 1:1로 변환하지만, `flatMap`은 각 요소 안에 들어있는 **컬렉션(상자)을 뜯어서 하나의 평평한 단일 스트림으로 합쳐줍니다.**

```java
List<OrderEntity> dbOrders = orderRepository.findByUserId(userId);

List<PurchasedItemUiDto> uiItemList = dbOrders.stream()
    // 1. [상위 필터링] 취소된 주문은 상자째로 제외
    .filter(order -> order.getStatus() != OrderStatus.CANCELED)
    
    // 2. [평탄화] 각 주문 내 상품 리스트(List<OrderItem>)를 하나의 스트림으로 펼침
    .flatMap(order -> order.getOrderItems().stream())
    
    // 3. [하위 필터링] 사은품(0원)은 제외하고 실제 결제 상품만 통과
    .filter(item -> item.getPrice() > 0)
    
    // 4. [UI 변환] 개별 상품을 UI용 DTO로 변환
    .map(item -> new PurchasedItemUiDto(item.getProductName(), item.getPrice()))
    .toList();
```

### 7.3 Null 안전 단건 처리 (`Optional` + `filter` + `map` + `orElseThrow`)
단건 조회(`findById`) 시 데이터가 없거나(`null`), 데이터는 존재하지만 비즈니스 규칙상 유효하지 않을 때 `if (user == null)` 분기문 없이 안전하게 처리하는 패턴입니다.
* **`Optional.filter()`의 동작**: 조건에 맞지 않으면 상자를 즉시 **빈 상자(`Optional.empty()`)**로 만들어 이후의 `.map()` 연산을 안전하게 건너뛰고 마지막 예외/기본값 처리로 직행합니다.

```java
public UserProfileUiDto getActiveUserProfileForUi(Long userId) {
    return userRepository.findById(userId)
        // 1. [필터링] 탈퇴 회원이면 빈 상자(Optional.empty)로 전환
        .filter(user -> user.getStatus() == UserStatus.ACTIVE)
        
        // 2. [필터링] 이메일 인증 완료 회원만 통과 (메서드 참조)
        .filter(UserEntity::isEmailVerified)
        
        // 3. [UI 변환] 정상 회원일 때만 실행되어 UI DTO 생성
        .map(user -> new UserProfileUiDto(
            user.getNickname(),
            user.getEmail(),
            "활성 회원"
        ))
        
        // 4. [예외 처리] DB에 없거나 필터에서 걸러졌다면 예외 발생 (Supplier 람다)
        .orElseThrow(() -> new IllegalArgumentException("조회할 수 없는 회원입니다."));
}
```

### 7.4 [보완] 데이터 그룹화 및 집계 (`Collectors.groupingBy`)
UI 화면에서 주문 내역을 **주문 상태별(배송중, 배송완료 등)**이나 **날짜별**로 묶어서(Map 형태) 보여주어야 할 때 사용하는 실무 핵심 최종 연산입니다.

```java
// 주문 상태(OrderStatus)를 Key로, 해당 상태의 UI DTO 리스트를 Value로 그룹화
Map<OrderStatus, List<OrderUiResponse>> groupedByStatus = dbOrders.stream()
    .filter(order -> order.getStatus() != OrderStatus.CANCELED)
    .collect(Collectors.groupingBy(
        OrderEntity::getStatus,                                  // 그룹화 기준 (Key)
        Collectors.mapping(this::convertToUiDto, Collectors.toList()) // 값 변환 및 수집 (Value)
    ));
```

### 💡 실무 패턴 핵심 요약 비교

| 구분 | `Stream` (`filter` + `flatMap`) | `Optional` (`filter` + `map`) |
| :--- | :--- | :--- |
| **다루는 데이터 규모** | **여러 건 (0 ~ N개)**의 컬렉션 데이터 | **단 건 (0 ~ 1개)**의 단일 객체 데이터 |
| **필터 조건 불만족 시** | 해당 요소만 스트림에서 제외되고 다음 요소 계속 처리 | 상자가 즉시 비워지며(`empty`) 이후의 `.map()` 모두 생략 |
| **주요 실무 활용처** | 게시글 목록, 다건 주문 내역, 1:N 하위 상품 추출 | 회원 상세 정보, 단건 결제 내역 조회 및 권한/상태 검증 |
| **Project Reactor 전환 시** | `Flux`의 `.filter()`, `.flatMap()`, `.map()`으로 그대로 대응 | `Mono`의 `.filter()`, `.map()`, `.switchIfEmpty()`로 그대로 대응 |
